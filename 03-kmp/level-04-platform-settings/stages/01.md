# M04.1 — Platform identity

## Concept
expect/actual declares a shared contract with platform-specific implementation. Prefer an interface for dependencies requiring runtime context; use expect/actual only where the platform boundary is stable.

## Prerequisites
Kotlin through coroutines/Flow, Android through repositories, and the preceding KMP stages. For level 1, start after the Android repository level; advanced Android can continue alongside this route.

## Mission
Implement expect platformName with actual values for Android and iOS.

## Observable completion
Each host shows its correct platform while using the same common call.

## Where to work
`shared/src/commonMain/kotlin/Domain.kt` contains `fun normalizedName(value:String): String`. Platform integration lives in `shared/src/androidMain`, `shared/src/iosMain`, `androidApp`, and `iosApp/App.swift`. Add focused types rather than accumulating every responsibility in the facade.

## Run
From this project folder:
```sh
./gradlew :shared:testAndroidHostTest
./gradlew :shared:iosSimulatorArm64Test
./gradlew :androidApp:installDebug
open iosApp/LearningApp.xcodeproj
```
Choose **LearningApp** and an iPhone simulator in Xcode, then Run. Read the root environment guide for JAVA_HOME and framework integration. Simulator execution does not require a paid developer account.
