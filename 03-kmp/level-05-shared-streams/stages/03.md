# M05.3 — Swift observation bridge

## Concept
StateFlow shares current state. Swift interop needs a deliberate observation boundary and a cancellation handle. A screen leaving must stop collection; shared scope ownership must be explicit.

## Prerequisites
Kotlin through coroutines/Flow, Android through repositories, and the preceding KMP stages. For level 1, start after the Android repository level; advanced Android can continue alongside this route.

## Mission
Use observe(callback) to update SwiftUI State and keep the returned cancellation handle.

## Observable completion
Two increments produce two visible updates; callbacks are delivered on the main dispatcher.

## Where to work
`shared/src/commonMain/kotlin/Domain.kt` contains `fun nextValue(current:Int): Int`. Platform integration lives in `shared/src/androidMain`, `shared/src/iosMain`, `androidApp`, and `iosApp/App.swift`. Add focused types rather than accumulating every responsibility in the facade.

## Run
From this project folder:
```sh
./gradlew :shared:testAndroidHostTest
./gradlew :shared:iosSimulatorArm64Test
./gradlew :androidApp:installDebug
open iosApp/LearningApp.xcodeproj
```
Choose **LearningApp** and an iPhone simulator in Xcode, then Run. Read the root environment guide for JAVA_HOME and framework integration. Simulator execution does not require a paid developer account.
