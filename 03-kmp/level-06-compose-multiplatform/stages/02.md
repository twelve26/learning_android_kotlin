# M06.2 — State and stable identity

## Concept
Compose Multiplatform shares UI descriptions across Android and iOS. Platform hosts still own application lifecycle and platform integrations. Decide which UI is worth sharing instead of assuming every screen should be shared.

## Prerequisites
Kotlin through coroutines/Flow, Android through repositories, and the preceding KMP stages. For level 1, start after the Android repository level; advanced Android can continue alongside this route.

## Mission
Use stable book IDs and an immutable selected set.

## Observable completion
Toggling one book does not change another; toggling twice restores original state.

## Where to work
`shared/src/commonMain/kotlin/Domain.kt` contains `fun toggle(ids:Set<Int>,id:Int): Set<Int>`. Platform integration lives in `shared/src/androidMain`, `shared/src/iosMain`, `androidApp`, and `iosApp/App.swift`. Add focused types rather than accumulating every responsibility in the facade.

## Run
From this project folder:
```sh
./gradlew :shared:testAndroidHostTest
./gradlew :shared:iosSimulatorArm64Test
./gradlew :androidApp:installDebug
open iosApp/LearningApp.xcodeproj
```
Choose **LearningApp** and an iPhone simulator in Xcode, then Run. Read the root environment guide for JAVA_HOME and framework integration. Simulator execution does not require a paid developer account.

<details><summary>Hint 2</summary>

</details>
