# M03.2 — Inject HTTP client

## Concept
Ktor exposes a common HTTP API while engines provide platform transport. MockEngine tests requests without accounts or network. Serialize at the boundary and keep transport details out of the domain.

## Prerequisites
Kotlin through coroutines/Flow, Android through repositories, and the preceding KMP stages. For level 1, start after the Android repository level; advanced Android can continue alongside this route.

## Mission
Implement BookRepository with a constructor-injected Ktor HttpClient and endpoint.

## Observable completion
MockEngine sees the expected URL and returns deterministic data.

## Where to work
`shared/src/commonMain/kotlin/Domain.kt` contains `fun parseBooks(text:String): List<Book>`. Platform integration lives in `shared/src/androidMain`, `shared/src/iosMain`, `androidApp`, and `iosApp/App.swift`. Add focused types rather than accumulating every responsibility in the facade.

## Run
From this project folder:
```sh
./gradlew :shared:testAndroidHostTest
./gradlew :shared:iosSimulatorArm64Test
./gradlew :androidApp:installDebug
open iosApp/LearningApp.xcodeproj
```
Choose **LearningApp** and an iPhone simulator in Xcode, then Run. Read the root environment guide for JAVA_HOME and framework integration. Simulator execution does not require a paid developer account.
